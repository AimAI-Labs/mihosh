Mihosh is organized as a layered Go application with explicit architectural boundary checks enforced in tests (`internal/arch_test.go` / `make arch-check`).

## Overall Package Structure

The project's dependency and composition flow is as follows:

```text
main.go
  ↓
internal/cli (Command Line Entry, Cobra) & internal/ui (Bubble Tea TUI, Themes, Styles)
  ↓
internal/bootstrap (Composition Root: wires config, clients, and services)
  ↓
internal/app/service (Application Services: ProxyService, ConnectionService, ConfigService, ProfileService, CoreService, SyncService)
  ↓
internal/domain (Pure Domain Layer — zero outer-layer dependencies)
  ├── model  (Core domain types & built-in theme catalog)
  ├── rules  (Rule canonicalization, parsing, formatting & edit models)
  └── port   (Consumer-scoped Mihomo API interfaces: ProxyAPI, ConnectionAPI, RuleAPI, ConfigReloader, RuntimeAPI, MihomoAPI)
  ↑ (implemented by)
internal/infrastructure (Adapters: api, config, core, host, profile, sync)
```

## Key Module Responsibilities

1. **Domain (`internal/domain`)**:
   - `model`: Core business entities (`Proxy`, `Group`, `Connection`, `Rule`, `MihomoConfig`, theme name catalog).
   - `rules`: Pure functions for rule canonicalization, key parsing, line formatting, and edit representation shared by config, profile, and UI.
   - `port`: Focused dependency-inversion interfaces implemented by `internal/infrastructure/api.Client`.
   - Depends only on the Go standard library and sibling domain packages.
2. **App (`internal/app/service`)**: Orchestrates business logic, configuration/override mutations, subscription workflows, and core lifecycle management. Never imports `internal/ui`, `internal/cli`, or `internal/bootstrap`.
3. **Bootstrap (`internal/bootstrap`)**: Centralizes runtime wiring (`NewApp`, `NewAppWithClient`, `NewClient`) for CLI and TUI entry points.
4. **Infrastructure (`internal/infrastructure/*`)**: Implements external adapters for the Mihomo HTTP/WebSocket API (`api`), YAML/app configuration (`config`), managed core binaries (`core`), OS services/network (`host`), subscriptions & snapshots (`profile`), and PostgreSQL/bundle sync (`sync`).
5. **Presentation (`internal/cli`, `internal/ui`)**:
   - `internal/cli`: Cobra command-line interface supporting `--output plain|table|json`.
   - `internal/ui/tui`: Feature-sliced Bubble Tea TUI with modular event routing (`update.go`, `update_ws.go`, `update_core_events.go`, `update_config_events.go`, `update_sub_events.go`).

## Data Flow & Boundary Enforcement

- In the TUI, Mihosh utilizes WebSocket subscriptions (traffic, logs, connections, and memory) for **real-time pushes**, avoiding high-frequency polling and reducing overhead.
- `internal/arch_test.go` verifies layer boundaries on every `go test ./...` run: `domain` stays isolated, `app` never imports `ui`/`cli`, `infrastructure` never imports `app`/`ui`/`cli`, and remaining legacy `ui -> infrastructure` edges are tracked in a strictly shrinking ratchet allowlist.
