Mihosh is designed based on **Clean Architecture** principles, ensuring high cohesion, low coupling, and excellent testability.

## Overall Package Structure

The project's request flow is as follows:

```text
main.go 
  ↓
internal/cli (Command Line Entry, Cobra)
  ↓
internal/app (Application Service Layer: ProxyService, ConnectionService, etc.)
  ↓
internal/domain/port (Dependency Inversion Interfaces: MihomoClient, ConfigRepository)
  ↓
internal/infrastructure (Infrastructure Implementation: HTTP/WS Clients, YAML Config Persistence)
```

## Key Module Responsibilities

1. **Domain**: `internal/domain/model` defines core business objects (e.g., `ProxyGroup`, `Connection`), `port` defines interfaces that infrastructure must implement. It does not depend on any other layers.
2. **App**: Orchestrates business logic by calling `port` interfaces to fetch data and execute logic.
3. **Infrastructure**: Implements interactions with external systems (Mihomo API, file system).
4. **UI**:
   - `internal/cli`: Command line interfaces.
   - `internal/ui/tui`: TUI built on top of the Bubbletea framework.

## Data Flow

In the TUI, Mihosh heavily utilizes WebSocket subscriptions (including traffic, logs, connections, and memory) for **real-time pushes**, avoiding high-frequency polling and reducing system overhead.
