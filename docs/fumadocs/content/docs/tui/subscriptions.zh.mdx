## 快捷操作

| 快捷键 | 操作说明 |
| --- | --- |
| `↑` / `↓` | 在订阅或规则集列表中上下移动选中项 |
| `u` | 立即拉取并更新当前选中的订阅或规则集 |
| `m` | 打开覆写设置 |
| `c` | 查看配置文件 |
| `n` | 添加新规则 |
| `e` | 编辑规则 |
| `d` | 删除规则 |
| `/` | 搜索特定的订阅名称 |

## 本地文件与预览

将 `.yaml` 或 `.yml` 配置放到 Mihosh 配置目录下的 `raw/`。启动、打开订阅页或刷新订阅页时会自动导入。导入时保存一份快照，源文件修改后可按 `u` 更新。删除订阅后，若要取消后续自动导入，可将源文件移出 `raw/`。

按 `c` 选择源文件快照、应用 `merge.yaml` 和已保存规则变更后的激活文件，或查看两者的差异。源文件和激活文件使用 Vim 打开只读临时副本，并使用 One Dark Pro 配色高亮 YAML。请确保 `vim` 在 PATH 中。未激活的订阅也可查看，退出 Vim 后会清理临时副本。差异在 100 列及以上并排展示，窄屏上下展示。

在差异视图中按 `o` 或点击底部的「差异选项」，可分别忽略缩进、其他空白、不可见字符（如 BOM 和零宽字符）、标点和符号。四项默认开启，调整后在切换订阅或重启 Mihosh 时继续生效。激活文件预览直接显示可打印的 Unicode 字符，差异比较将同一个字符及其转义写法视为相同。

## Mihomo 覆写

按 `m` 编辑 `merge.yaml`，使用与订阅相同的 Mihomo 原生字段。`rules`、`proxies` 和 `proxy-groups` 等列表会整体替换订阅里的对应列表。删除相应字段即可恢复使用订阅列表。

Mihosh 保存旧版覆写时，会把规则前置、追加和编辑指令迁入 `rule-edits.yaml`，并保留原始文件 `merge.yaml.legacy-*.bak`。旧版节点和代理组指令根据激活订阅或本地配置转换为原生列表。

### 订阅规则维护建议

- **日常跟随订阅更新**时，保留订阅提供的规则列表，用规则页增删改。只有自行维护整张规则表时，才在 `merge.yaml` 中填写 `rules`。规则页保存的变更也会应用到这张自定义列表上。
- **刷新或切换订阅后**，按 `c` 查看「激活文件」或差异，确认自定义规则在预期位置。若两条规则都能匹配同一流量，优先检查哪条排在前面。精确例外应在宽泛匹配之前，`MATCH` 应在最后。[规则管理](/docs/tui/rules)

## 界面特性

- **配置与规则集统管**：不仅可以管理节点订阅 (Proxy Provider)，也可以管理分流规则的订阅 (Rule Provider)。
- **实时进度反馈**：在执行更新操作时，右侧面板会展示更新进度、拉取耗时以及是否有错误发生。
