## 首次使用

运行 `mihosh`，进入导航栏 **Core** 菜单。没有内核和订阅也能进入应用。

首次进入时，选中「一键开始使用」并按 `Enter`，自动安装内置校验版本、生成 DIRECT 基础配置并启动。随后进入订阅页添加订阅 URL 或本地 Mihomo 配置。

没有订阅时，基础配置提供直连能力，不会自动提供代理节点。系统代理、终端环境变量和 TUN 各自独立；内核运行不代表所有应用已接入代理。

「运行与代理」顶部固定显示标签栏和一行状态摘要，操作分为内核运行、代理开关和维护。完整路径和服务状态可在「内核详情」查看。停止或重启内核需要确认。「下载管理」在同一页显示内核版本和 GEO 文件，「Mihomo 配置」提供覆写表单，Linux 托管模式下，「配置项」下方显示 `systemctl --user status` 的状态和最近 10 条日志。开关显示保存的设置，实际网络效果取决于内核运行状态。宽屏采用 43% / 57% 双栏，窄屏纵向排列。表单使用 `Tab` 切换字段、`Enter` 保存。会话模式退出应用会停止该会话拥有的内核，服务模式退出 TUI 后继续运行。已有外部内核由原有程序管理。

## GEO 管理

Core 中按 `4` 查看托管内核的 `Country.mmdb`、`GeoIP.dat`、`GeoSite.dat`、`ASN.mmdb`。「GEO 数据文件」卡片顶部显示保存目录，列表显示实际文件名、大小和修改时间。缺失文件标为「尚未下载」。选中文件后按 `Enter` 或点击下载、更新，复用 Core 中配置的代理、加速链和 SHA-256 校验；更新完成后按 `z` 重启内核生效。

保留已有文件别名与配置中的官方精简数据集；自定义来源标记为通过内核管理。外部内核仍在「Core → Mihomo 配置」中更新 GEO。

## 可视化版本选择

进入 Core 后按 `2`，直接浏览官方稳定版本。下载管理优先显示 Mihosh 配置目录下 `core/releases-cache/` 中的缓存列表。缓存达到 24 小时或缺失时，打开页面会在后台查询最新列表。列表按本机系统和架构匹配下载文件，显示版本号、发布日期、文件大小，以及「当前选用」「已下载」状态。每次按需查询最多 10 条官方发行记录，过滤测试版、草稿和不兼容文件后追加到同一列表，并按版本号去重。方向键或滚轮浏览接近末尾时，自动加载更早版本，直到官方列表结束；中间没有适配版本的批次会自动跳过。已加载记录保存在本次会话的临时目录，内存固定缓存最多 64 条，并仅渲染可见行；可以回看全部已加载版本。退出应用时清理临时目录。

使用方向键或鼠标选择版本，左侧显示对应文件和下载操作。**选择只改变页面上的目标，下载也不会切换或重启当前内核。** 按 `Enter` / `i` 下载；下载完成后，再明确按 `a` 使用该版本，运行中的托管内核届时可能重启。已经选用的版本不会重复切换。

`PgUp` / `PgDn`（也可按 `[` / `]`）在连续列表中按段浏览，`End` 跳到已加载末尾并触发后续加载，也可点击「加载更多」。底部显示已加载数量、加载中或「全部适配版本已加载」。`r` / `v` 刷新会重新读取最新列表，成功后替换旧快照；`t` 可直接查找稳定版本。加载失败保留全部已显示数据并暂停自动重试，按 `r` 或点击「重试」从失败批次继续。首次查询失败时仍可使用内置校验版本或已有单版本缓存；页面会注明该数据并非最新官方列表。缺少可信 SHA-256 时禁用下载，可重试官方直连／代理线路，或按 `l` 导入独立核对过的本地文件。

交互参考 [Clash Verge Rev 的内核管理组件](https://github.com/clash-verge-rev/clash-verge-rev/blob/dev/src/components/setting/mods/clash-core-viewer.tsx) 的列表、状态标签及独立操作按钮，并扩展为全部适配 Mihomo 稳定历史版本的连续懒加载浏览。数据来自 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#list-releases)，继续复用本应用的下载回退、来源限制和摘要校验。

## CLI

```bash
# 安装校验版本并生成基础配置，暂不启动
mihosh setup --output json

# 前台运行；另一个终端可以停止或重启该托管会话
mihosh core start
mihosh core status --output json
mihosh core restart --output table
mihosh core stop --output plain

# 查询、安装与切换稳定版本
mihosh core releases --output table
mihosh core install --version v1.19.33 --output json
mihosh core activate --version v1.19.33 --output json
mihosh core upgrade --output json
mihosh core rollback --output json
```

`core install` 省略 `--version` 时使用随应用记录的已校验版本；指定版本时查询官方发行信息。安装和版本选择分别进行，不覆盖外部软件安装的内核。

本地导入要求**解压后的可执行文件**和已独立核对的该文件 SHA-256；压缩包摘要不能用于校验解压后的文件。

```bash
mihosh core import --file /path/to/mihomo --version v1.19.33 --sha256 "YOUR_VERIFIED_SHA256" --output json
mihosh core configure --output json
```

`setup` 与全部 `core` 子命令支持 `--output plain|table|json`。前台 `start` 等待停止或中断后返回最终结果；关闭拥有该会话的前台命令会停止子进程。服务模式的 `start` 在后台就绪后返回，不等待服务停止。

## 后台服务与自动启动

Core 菜单按 `h`，使用方向键或鼠标滚轮选择「安装后台服务」，按 `Enter` 执行；`Esc` 返回。安装时会自动将正在运行的会话内核交接至后台服务；后台启动失败时恢复会话内核。安装会将当前 Mihosh 复制到 `~/.mihosh/bin/`，作为固定的服务入口，并将 `core.runtime` 切换为 `service`。之后 `s` / `x` / `z` 和 `core start/stop/restart` 操作后台服务。关闭 TUI 不会停止服务；订阅、升级和回滚通过私有控制入口交给拥有内核的后台会话执行。

```bash
mihosh core service install --output json
mihosh core service enable --output json
mihosh core start --output json
mihosh core service status --output json
mihosh core service boot --output json
mihosh core service disable --output json
mihosh core service uninstall --output json
```

Linux 使用 systemd **用户服务**。`enable` 立即启动并随用户登录启动；`boot` 立即启动并额外调用 `loginctl enable-linger`，允许用户管理器在开机、未登录时运行，可能需要系统授权。卸载只删除本应用按配置根目录生成的服务单元，保留订阅、内核和备份；不会关闭用户的 linger，以免影响其他用户服务。服务失败启动受次数与时间窗口限制。内核日志写入用户 journal，可用 `mihosh service logs` 查看。

Mihosh 自身升级后，可停止服务并重新安装固定入口。既有 `mihosh service` 在托管模式且未指定 `--unit` 时使用托管目标；显式 `--unit` 保留原有外部 systemd 服务语义。

## 系统代理、TUN 与恢复

```bash
mihosh core system-proxy on --output json
mihosh core system-proxy off --output json
mihosh core tun on --output json
mihosh core tun off --output json
mihosh core network-recover --output json
```

这些命令与 Core 的 `y` / `n` / `c` 共用实现，均支持 `--output plain|table|json`。开关保存期望设置；未运行时不会宣称已改变系统流量。TUN 变更先校验候选配置；运行中会受控重启，失败恢复旧配置与开关。下载代理、终端 `on/off`、系统代理和 TUN 各自独立。

本轮 P2／P3 仅支持 Linux。系统代理使用 GNOME 的 GSettings，需要用户 D-Bus；其他桌面环境会在修改前拒绝。启用代理时先记录原值，关闭或拥有会话退出时，只恢复仍与本应用写入值一致的字段，保留期间用户另行修改的字段。

TUN 默认关闭。Linux 需要 `/dev/net/tun`、iproute2，且 **Mihosh 协调进程和恢复守护进程**需要 `CAP_NET_ADMIN`；不能只给内核可执行文件授权。对已安装的固定服务入口，可由管理员明确授权：

```bash
sudo setcap cap_net_admin,cap_net_raw+ep "$HOME/.mihosh/bin/mihosh"
```

前台模式应给实际运行的 Mihosh 可执行文件授权；更新或重新复制文件后需重新核对能力。不会静默提权。

托管 TUN 使用独立名称、路由表和规则区间，预先检查冲突。采用系统协议栈、自动路由和出口接口检测，不启用额外自动重定向或严格防火墙规则。DNS 不对外监听；保留已有 nameserver，缺少时生成 Cloudflare/阿里 DoH 与引导 DNS。系统 DNS 的接口配置随托管 TUN 一起恢复。

修改前将恢复记录写入 `runtime/network-recovery.json`；TUN 切换还使用 `network-change.json` 恢复中断的配置变更。独立守护进程在拥有进程退出后恢复代理并清理本应用的 TUN 网络；systemd 模式将守护放入单独的临时用户服务单元。恢复失败保留记录供重试；`network-recover` 仅在运行锁证明没有活动拥有者时执行，不接管其他内核或清理其他接口。`core status` 显示运行方式、自动启动、期望的代理/TUN 开关和待恢复状态。

## 原生验收

普通 `go test ./...` 不修改真实系统服务或桌面代理。Linux 可运行 `scripts/test-managed-core-linux.sh`，依次选择 `isolated`、`service`、`tun` 或 `proxy`；传入已独立校验的本地内核路径与 Mihosh 路径。`tun` 模式在独立用户/网络命名空间创建测试出口。原生代理测试需明确设置 `MIHOSH_ALLOW_NETWORK_CHANGES=1`。

`scripts/test-managed-core-container.sh` 提供带 TUN、D-Bus 和 GNOME 设置后端的隔离 Linux 验收环境，不挂载宿主目录、不发布端口，默认验收后删除容器；传入 `--keep` 可保留环境。原生 systemd 生命周期可通过 `test-managed-core-linux.sh service` 在本机单独验证：仅安装独立命名的临时服务，硬限内存 256 MiB，不开启系统代理或 TUN。实际验收结果见方案实施记录。

## 下载回退与校验

每次发行查询和资产下载依次尝试：**官方直连 → 可用 HTTP(S) 代理 → GitHub 加速网址**。没有代理时跳过代理阶段；直连与加速站请求显式禁用环境代理。代理阶段按显式配置、适用的环境代理、具备节点的托管代理顺序尝试，环境代理遵循 `NO_PROXY`。

内置 `https://gh-proxy.org/` 与同服务兼容入口 `https://gh-proxy.com/`。进入 Core 的下载管理，按 `e` 可更改顺序、追加入口或留空禁用。高级能力可在应用配置中指定：

```yaml
core:
  proxy: ""
  download_timeout_seconds: 600
  accelerators:
    - url: https://gh-proxy.org/
      metadata: true
      asset: true
```

下载总时限可设为 30–3600 秒，`0` 使用默认 600 秒；各线路时限随总预算缩放。省略 `accelerators` 使用默认列表；`accelerators: []` 禁用加速站。仅支持资产的站点将 `metadata` 设为 `false`。

加速站用于传输公开 GitHub 资源，不接收订阅地址、控制器 secret 或 GitHub Token。加速元数据本身不能建立资产可信性：安装仍需匹配内置官方摘要，或由官方直连/代理连接取得的有效摘要。缺少可信摘要时安装会失败，不会跳过校验。

下载具有总时限、单线路时限、一次有界重试和进度显示。切换线路重新下载；未校验的 `.part` 文件不会替换已安装版本。第三方入口返回错误时可重试、调整网络设置或改用本地导入。

## 模式与文件

托管文件位于 `~/.mihosh/core/versions/<版本>/` 和 `~/.mihosh/runtime/`；每次安装记录来源、摘要和上游源码/许可链接。`core` 配置选择托管模式与版本，托管控制器及代理端口以 `runtime/config.yaml` 为准。`MIHOSH_CONFIG_DIR` 可指定绝对配置根目录，服务入口通过 `--home` 固定它；配置、订阅和备份使用同一根目录。

外部 API 连接保留原安装方式。显式外部连接不绑定本地文件，Mihosh 不会为其写入默认本地 Mihomo 配置。

订阅激活先生成并校验候选文件，再应用；失败时恢复旧配置和激活记录。托管导入保留本地控制器与代理端口，按 Core 中明确选择的 TUN 开关生成托管网络配置，并清除订阅附带的其他监听入口。订阅不能自行启用 TUN。升级中断记录和配置恢复记录在下次启动时处理。

当前资产选择覆盖 Linux/Windows 的 amd64 compatible 与 arm64。Linux amd64 已通过真实内核验证；其他目标的构建与实际运行验证情况见方案中的实施记录。

## Mihomo 配置

进入 **Core → Mihomo 配置**（`p` 或 `5`），可编辑 `merge.yaml` 中的五项覆写，包括 `external-controller`、`secret`、`mixed-port`、`allow-lan` 和 `log-level`。用方向键或滚轮选择，按 `Enter` 或双击进入编辑，再按 `Enter` 保留草稿，或按 `Esc` 取消本次编辑。枚举值也可直接点击。将 `allow-lan` 或 `log-level` 选为「空」会从 `merge.yaml` 删除对应键。选择 `false` 会显式写入 `allow-lan: false`。

点击「覆写」、选中按钮后按 `Enter`，或按 `Ctrl+S`，即可写入 `merge.yaml` 并立即重新生成和应用激活配置。从订阅页编辑 `merge.yaml` 后，表单也会刷新。若提示本地外部内核需要重启，重启后在 Core 按 `r` 重新连接。远程控制器应用的配置在内存中生效，持久化需更新远端的配置文件。
